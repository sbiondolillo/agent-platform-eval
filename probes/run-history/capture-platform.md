## 4. The factory's own files

### Where the transcript is written

`dotnet-software-factory` v1.2.1, `src/Core/Sandbox.cs:31-35`:

```
// The home is a directory on the host, so the transcript that Claude Code writes under it outlives the container.
// The process that creates it owns it, and that is the user the container runs as.
string home = Path.Combine(rootDirectory, ".factory", "sandbox-home", Guid.NewGuid().ToString("N"));
Directory.CreateDirectory(home);
List<string> volumes = ["--volume", $"{workTree}:/work", "--volume", $"{home}:{Home}"];
```

`Home` is `/tmp/sandbox-home` (`src/Core/Sandbox.cs:9`), and the container gets `HOME=/tmp/sandbox-home` (`src/Core/Sandbox.cs:58`). Claude Code in the container writes its JSONL transcript under `$HOME/.claude/projects/`. The bind mount puts that file at `.factory/sandbox-home/<guid>/.claude/projects/-work/<session-id>.jsonl` in the factory's checkout on the runner host. `.factory/` is in the factory's `.gitignore` (`.gitignore:1`).

Other files the factory writes under `.factory/` in the work tree are phase hand-offs, not run records:

| file | source |
|---|---|
| `.factory/plan.md` | `src/Core/PlanPhase.cs:16` |
| `.factory/review.json` | `src/Core/ReviewPhase.cs:12` |
| `.factory/threads.json` | `src/Core/FeedbackRun.cs:32`, the feedback run's report |

No file named "Report" or "transcript" is written anywhere else. The `Report` matches in `src/` are the feedback report above and the TRX test report reader, `src/Core/TestReport.cs`.

### The transcript store step in the starter

The starter workflow at v1.2.1 has a step that copies the transcripts to a private store repo, `templates/starter/.github/workflows/factory.yml:40-67`. The key lines:

```
40	      - name: Push the transcripts to the store
41	        # The store is a private repo. With no store, the step exits 0 at once. The log prints no transcript.
42	        if: always()
...
47	          if [ -z "$STORE_REPO" ] || [ -z "$STORE_DEPLOY_KEY" ]; then exit 0; fi
...
55	          mkdir -p "$store/runs/$GITHUB_RUN_ID"
56	          if [ -d .factory/sandbox-home ]; then
57	            find .factory/sandbox-home -type f -name '*.jsonl' -exec cp --parents -t "$store/runs/$GITHUB_RUN_ID" {} +
58	          fi
```

The step came in after v1.1.0: `git log --oneline v1.1.0..v1.2.1 -- templates/starter/.github/workflows/factory.yml` shows `31cff52 feat(workflows): push the sandbox transcripts of a factory run to a private store repo (#300)`. The target repo was made from the v1.1.0 starter. Its `.github/workflows/factory.yml` on `main` has three steps, checkout, setup-dotnet and "Run the factory" (lines 28-46), and no store step. The target repo also holds no Actions secret, so no `STORE_REPO` is set. This arm has no transcript store.

One home directory holds 5 transcripts, from 17:56 to 18:00 UTC. That is run 40118345316, the last run on this runner. The homes of the earlier runs are gone. `actions/checkout` runs `git clean -ffdx` before each fetch by default (input `clean`, default `true`, https://github.com/actions/checkout#usage), and `-x` also removes ignored paths such as `.factory/`. So the transcripts of a run stay on the runner host only until the next run starts. Only the lab operator can read them, over SSH to `sandbox-01`.

## 5. The gateway ledger

Not queried again. The cloud-logging probe recorded its shape ([`../cloud-logging/capture-platform.md`](../cloud-logging/capture-platform.md#gateway-ledger)). `telemetry.gateway_calls` on the lab ClickHouse holds one row per model call, with consumer, model, status, tokens, cost and time. The operator reads it as role `mcp_ro` from the Management VLAN. Factory v1.2.1 sends no run id, so a run's rows are matched by consumer `dsf` and the job's time window. The table moves rows to cold storage after 90 days and deletes none. The probes read only its spend and status columns, so here it counts as a per-call record, not a transcript. This probe did not check whether the table also stores request or response bodies.
